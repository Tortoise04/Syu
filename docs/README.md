# Syu 文档索引

两级分开：**可公开**（进仓库，任何人可读）与**仅本地**（含真实群号/案例/内部分工，不同步、不进仓库）。
判断一条材料该放哪一层，看一个问题：*这段文字明天出现在别人的搜索结果里，会不会给群里的人带来麻烦。*

## 一、可公开（进仓库）

| 文档 | 读者 | 内容 |

| [`../README.md`](../README.md) | 第一次看这个项目的人 | 一句话定位、判定顺序、模块地图、配置、快速上手、实测数字、已知边界 |

这两份文档的口径纪律：只写可核实的东西（能对到代码行、能对到测试输出、能对到配置文件），不写评价性形容词，不写"彻底解决""极大提升"这类无法证实的句子。真实群号、真实 QQ、真实词表、真实群聊原文一律不出现。

## 四、怎么读

- **只想跑起来**：`../README.md` 的[快速上手](../README.md#快速上手)。
- **想改判定逻辑**：先读 [`architecture.md`](architecture.md) 第 3 节（主链路）与第 5 节（数据契约），再看 `src/guard/pipeline.ts` 的 `handleMessage()`。
- **想调阈值/词表**：`../README.md` 的[配置](../README.md#配置) + [`architecture.md`](architecture.md) 第 11 节（热加载，改完 1 秒生效）。
- **想评估能不能上自己的群**：`../README.md` 的[已知边界](../README.md#已知边界) + [`architecture.md`](architecture.md) 第 15 节（设计取舍与代价）。
- **想复盘某条判定**：`data/violations.jsonl` 里找那一行的 `channel`/`rule`/`confidence`/`reason`，抽样相关的看 `sampleRoll` 与 `sampleRate`，然后用 [`architecture.md`](architecture.md) 第 7 节的算法复算。

## 五、维护

改代码后要同步的段落：

| 改了 | 同步哪里 |
|---|---|
| 判定顺序或闸门 | `README.md` 判定顺序表 + `architecture.md` 第 3 节 |
| 新增/删除模块 | `README.md` 模块地图（含行数）+ `architecture.md` 第 4 节 |
| 数据契约字段 | `architecture.md` 第 5 节 |
| 测试脚本或条数 | `README.md` 脚本与测试表 + `architecture.md` 第 13 节 |
| 入库规则 | `PUSH_RULES.md` §7 先加一行变更记录，再改正文 |

文档与代码不一致时，以代码为准，并在 `architecture.md` 第 14 节点名偏差——不要在文档里悄悄改成"看起来对"的样子。
